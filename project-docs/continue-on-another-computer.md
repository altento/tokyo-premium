# Продолжить работу с Tokyo Premium на другом компьютере

Эта инструкция переносит **код и историю Git** на другой компьютер. Локальная переписка Codex может не синхронизироваться между компьютерами, поэтому продолжайте работу из репозитория и сначала дайте Codex прочитать `AGENTS.md` и этот файл.

## 1. Клонировать проект

Установите Git for Windows, откройте PowerShell и выполните:

```powershell
git clone https://github.com/altento/tokyo-premium.git
Set-Location .\tokyo-premium
git status --short --branch
```

Если репозиторий приватный, войдите в GitHub через Git Credential Manager. Не вставляйте пароль GitHub, SMTP-пароль, ключ FreedomPay или другой секрет в чат Codex, исходный код, `.env.example` или Git.

## 2. Открыть репозиторий в Codex

В Codex Desktop выберите **Open folder / Открыть папку** и укажите папку `tokyo-premium`. Создайте новый чат и отправьте короткую команду:

> Прочитай AGENTS.md и project-docs/continue-on-another-computer.md. Продолжай работу в актуальном состоянии ветки main, сохраняя существующие изменения и данные. Сначала проверь git status.

Для продолжения не нужно передавать старую локальную переписку: незакоммиченная работа должна быть отправлена в Git перед переносом.

## 3. Запустить PHP-версию локально

Нужны PHP 8+ с расширением PDO SQLite и PowerShell. В корне репозитория:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\Start-Tokyo.ps1 -Port 8081
```

Скрипт проверит PHP/SQLite, создаст базу, применит безопасные миграции и напечатает адрес `http://127.0.0.1:8081`. Оставьте окно PowerShell открытым. Для остановки нажмите `Ctrl+C`.

Адрес панели управления: `http://127.0.0.1:8081/admin.php`. Для нового локального окружения создайте администратора **один раз** в другом окне PowerShell:

```powershell
Set-Location .\tokyo-premium
.\Start-Tokyo.ps1 -SetupAdmin
```

Скрипт запросит email и новый пароль. Не используйте пароль от Gmail. Если администратор уже существует в выбранной базе, повторно этот шаг не запускайте.

## 4. Локальная база данных

По умолчанию `Start-Tokyo.ps1` хранит базу вне Git, в `%LOCALAPPDATA%\TokyoPremium\data\restaurant.sqlite`. Устаревший ручной PHP-сервер мог использовать `%TEMP%\tokyo-restaurant.sqlite`. Чтобы выбрать уже существующую базу, укажите её **перед запуском**:

```powershell
$env:RESTAURANT_DB = Join-Path $env:TEMP 'tokyo-restaurant.sqlite'
.\Start-Tokyo.ps1 -Port 8081
```

Машинная SQLite-база намеренно не входит в репозиторий: в ней могут оказаться аккаунты, email, бронирования и админские хеши. При переносе на новый компьютер запускается отдельная база. Для повторяемого демонстрационного содержимого используются миграции и seed-файлы репозитория; реальные данные базы переносите только отдельной защищённой копией.

## 5. Статическая версия и публикация

PHP и SQLite локально обслуживают динамическую версию. GitHub Pages показывает статический демонстрационный экспорт из `docs/`: он не создаёт реальные заказы, брони, письма, платежи и админ-сессии.

Push в `main` запускает существующий workflow `.github/workflows/pages.yml`; после его успешного завершения проверьте [публичную страницу](https://altento.github.io/tokyo-premium/). Не загружайте SQLite, SMTP-пароли, API-ключи и локальные `.env`-файлы.

## 6. Обычный цикл Git

Перед изменениями:

```powershell
git pull --ff-only
git status --short --branch
```

После проверяемой работы:

```powershell
git add <изменённые-файлы>
git diff --cached --stat
git commit -m "Describe the change"
git push origin main
```

Если в `git status` есть неизвестные базы, `.env`, логи, временные архивы или учётные данные, не добавляйте их. Сначала разберитесь с источником. Не используйте `git reset --hard`, очистку рабочей папки или принудительный push без отдельной осознанной причины.

## 7. Что уже предусмотрено в проекте

- Меню хранит блюда и состав в SQLite; миграции `19` и `20` аддитивно расширяют каталог до 50 публичных позиций и связывают новые позиции с ингредиентами, тегами и сочетаниями.
- На широких экранах каталог показывает 12 позиций на странице, на телефонах — 6. Кэш изменяемых стилей и скриптов сбрасывается по времени изменения файла.
- Запуск PHP выполняет миграции автоматически. Не редактируйте production-базу вручную, если ту же задачу можно выполнить миграцией.
- Текущие новые карточки используют имеющиеся локальные изображения наиболее близких блюд; у каждой из 29 новых позиций ещё нет отдельной уникальной фотографии.
- Настройка отправки email описана в `project-docs/booking-email.md`; отправитель должен быть настроен через переменные окружения PHP.
- FreedomPay адаптер описан в `project-docs/freedompay-payments.md`; реальная оплата требует merchant account, секретов вне Git и доступного PHP-хоста на HTTPS.
- Домашний хостинг и удалённый доступ описаны в `project-docs/home-hosting.md`.
