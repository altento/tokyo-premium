# Menu header at tablet width — 2026-11-17

Compared the current menu against `design-references/02-menu.png` after a review raised a possible 1024 px catalog-column regression. The current catalog already had three columns at 1024 px; that part of the report did not reproduce.

The actual visible mismatch was the header: the approved reference keeps its desktop navigation, profile, and cart at 1024 px, while the site had switched to a mobile menu. Source and Pages CSS and `navigation.js` now use the same 1023 px breakpoint. The compact desktop header at 1024 px shows its navigation, profile, cart, and booking action inside the header padding without overlap; the booking link retains the accessible name “Бронировать столик.” At 1023, 900, and 390 px the mobile menu remains available, keeps navigation inert while closed, exposes the booking link while open, closes with Escape, and restores focus to its trigger.

The focused `npm run test:menu-visual` static run passed at 1440, 1024, 1023, 900, and 390 px. The existing CI visual-fidelity suite was also run locally in static menu mode and passed its 1024/1023 header-boundary, keyboard, and accessible-name assertions. The menu test verified the expected three-column catalog at 1440/1024/1023, two columns at 900/390, no horizontal overflow, and existing menu search/filter checks. The current desktop/tablet/mobile captures are in this directory; `baseline/menu-static-1024-before.jpg` records the earlier collapsed header. PHP rendering was not checked locally during this pass, and hosted validation of this change is pending.
