## Оставшиеся пункты

1. **GitHub Pages** — отправить проверенный код и документацию в `main`, дождаться успешного workflow и проверить опубликованную страницу. Старый опубликованный SHA до этого шага остаётся активным.
2. **SprintHost PHP-версия** — разместить PHP-приложение и подключить постоянную SQLite-базу. Текущая панель требует ручного входа; после входа можно продолжить загрузку из открытой сессии. До этого нельзя подтвердить путь к сайту, права на запись, сохранность SQLite и фактический PHP-стек хостинга.
3. **Отдельные фотографии каталога** — у части новых блюд используются повторяющиеся локальные изображения. Для полного соответствия карточек блюдам нужны согласованные фотографии или отдельный пакет сгенерированных учебных изображений.
4. **Проверка фактов ресторана** — меню, цены, адрес, телефон, режим, состав и аллергены вымышлены. Их можно публиковать как реальные только после сверки владельцем.
5. **Внешние сервисы** — HTTPS PHP-хостинг, SMTP и параметры FreedomPay не настроены. Пока они не заданы, настоящая отправка писем, подтверждение брони и оплата недоступны; GitHub Pages остаётся статической демоверсией.

## Базы и перенос между компьютерами

- В каталоге 52 записи блюд: 50 доступны публично и 2 защищены Secret Menu. Бизнес-фикстуры не являются частью Git.
- Локальная база проверки содержит 12 учебных заказов, 8 броней, 10 обращений и 10 отзывов. Её путь находится вне репозитория; этот файл нельзя переносить в GitHub Pages или коммитить.
- На новом компьютере `Start-Tokyo.ps1` создаёт/обновляет SQLite вне репозитория. Для локальной проверки кабинета и админских списков можно один раз отдельно запустить `php tools/seed-demo-data.php --apply`; команда печатает случайный пароль в локальную консоль.
- Подробная инструкция переноса и ограничения GitHub Pages/SprintHost: [continue-on-another-computer.md](continue-on-another-computer.md) и [deployment.md](deployment.md).
