## Что сейчас находится на SprintHost

Это отдельная PHP-версия; её нельзя считать обновлённой публикацией Pages.

- Активная база — SQLite-файл в закрытом каталоге `private-data/`, вне `public_html`; права файла `600`, каталога `700`. `.htaccess` запрещает выдавать базу через веб и указывает приложению именно на активный файл `tokyo-restaurant-public50.sqlite`.
- В активной базе: 52 блюда (50 публичных и 2 закрытых), 8 категорий, 36 аккаунтов, 104 заказа, 305 строк заказа, 52 брони, 34 отзыва, 76 записей лояльности, 6 сезонных коллекций и 39 связей коллекций с блюдами. Значения строк и контактные поля здесь намеренно не перечисляются.
- Целостность SQLite — `ok`; внешние ключи не показывают нарушений. База не изменялась во время аудита.
- На SprintHost присутствуют ещё две копии SQLite. Активной является только `tokyo-restaurant-public50.sqlite`, что подтверждено настройкой `RESTAURANT_DB` в `.htaccess`.
- Версия базы на хостинге — миграция 21; код в Git требует миграцию 22. Развёртывание текущего PHP-кода и применение миграции на хосте ещё не выполнялись.
- Технический домен `f1338748.xsph.ru` отвечает по HTTP, а проверка HTTPS завершается ошибкой сертификата. В [справке SprintHost о технических доменах](https://help.sprinthost.ru/how-hosting-work/techdomain) указано, что они работают только по HTTP. Кабинет, формы входа и оплаты на таком адресе нельзя считать защищёнными; не вводить реальные пароли, персональные данные или платёжные сведения. Для TLS потребуется домен владельца, подключённый к хостингу, либо уже доступный PHP-хостинг с HTTPS. Баланс панели — 0 ₽; покупок и смены тарифа не было.
- MySQL/PostgreSQL не нужны: приложение рассчитано на SQLite, отдельный DbaaS не создан.

## Оставшиеся задачи по приоритету

### P0 — безопасный PHP-релиз

- [ ] Подключить уже принадлежащий владельцу домен с валидным HTTPS либо использовать уже доступный PHP-хостинг с HTTPS. Технический домен `.xsph.ru` работает только по HTTP; новый домен/тариф не покупать без отдельного решения владельца.
- [ ] Перед выкладкой сделать резервную копию активной SQLite-базы и проверить PHP 8+, PDO SQLite и права записи.
- [ ] Загрузить актуальный PHP-код, сохранить путь `RESTAURANT_DB` к существующей базе, выполнить миграцию 22 и проверить бронирование, кабинет, корзину и административные сценарии. Не заменять активную базу копией из Git или Downloads.

### P1 — каталог и содержание

- [ ] Развести повторяющиеся фото блюд: сейчас у 52 строк каталога 21 уникальный путь изображения, при этом пустых путей нет. Для каждого блюда нужны согласованные изображения либо отдельный пакет учебных фото.
- [ ] Если проект станет реальным сайтом, владелец должен сверить названия, состав, аллергены, цены, адрес, телефон, график и все сезонные предложения. До этого тексты и значения остаются вымышленными.

### P2 — внешние сервисы реального ресторана

- [ ] Для реальных писем отдельно настроить SMTP и проверить доставку подтверждений.
- [ ] Для реальной оплаты нужны HTTPS, merchant-аккаунт FreedomPay и секреты в переменных окружения вне Git.
- [ ] Для живой доступности столов нужна интеграция с фактической системой рассадки; сейчас форма не обещает реальное наличие.
