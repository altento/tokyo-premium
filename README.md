# Tokyo Premium — ресторан японской кухни

Существующий PHP-проект продолжен из резервной копии. Проект включает PHP 8.1+ приложение с SQLite и публичную статическую демоверсию на GitHub Pages. Все ресторанные сведения, меню, адрес, телефон, расписание, отзывы и цены придуманы для лабораторной работы.

Перенос разработки на другой компьютер, запуск локальной версии и безопасная работа с Git: [`project-docs/continue-on-another-computer.md`](project-docs/continue-on-another-computer.md).

Проверка бронирования и галереи: `npm run test:floorplan`, `npm run test:gallery-caption`, `npm run test:booking-gallery-layout`. Задайте `TOKYO_BASE_URL` и `TOKYO_STATIC_BASE_URL` адресами запущенных PHP и статической версий. Сброс бронирования очищает предпочтительный стол; фотографии залов и отфильтрованная галерея листаются отдельными группами. [Скриншоты и сравнение](project-docs/visual-qa/booking-gallery-2026-11-19/comparison.md).

## Запуск PHP-версии

Каталог сортирует весь список до деления на страницы; обновление избранного сохраняет текущую страницу. Быстрый просмотр сообщает результат внутри окна. Кнопки добавления отклоняют превышение лимита целиком, без частичного добавления. Проверка: `npm run test:menu-state` с `TOKYO_BASE_URL` / `TOKYO_STATIC_BASE_URL`; для одной версии — `TOKYO_MENU_STATE_MODE=php` или `static`.

Бронирование проверяет дату и время по часовому поясу ресторана: прошедшие часы недоступны, исправленная дата снимает прежнюю ошибку. PHP проверяет будущий момент повторно. Номера и зоны столиков берутся из SVG-схемы (42 варианта); при сбое загрузки схемы можно указать только зону. Это пожелание, не проверка свободных мест. Проверки: `npm run test:booking-time-integrity` и `npm run test:booking-time-browser`.

Кабинет демоверсии сохраняет черновик профиля при обновлении избранного и предупреждает об изменении сохранённого профиля в другой вкладке. Пустые/повторные адреса отклоняются; при лимите 10 старые адреса сохраняются. Ошибки хранилища отображаются явно. Проверка: `npm run test:account-resilience` с `TOKYO_STATIC_BASE_URL`. PHP-настройки сайта сохраняются атомарно, пропущенные поля остаются без изменений: `npm run test:admin-settings-integrity`.

Marketing & Loyalty: редактирование описания кампании сохраняет текущие остатки и доступность подарков. Меняйте их отдельной формой «Настроить остаток и доступность подарка». Дубликат нового промокода отклоняется; существующий код редактируется через «Изменить условия». Проверки: `npm run test:admin-marketing-integrity` и `npm run test:admin-marketing-browser` (изолированные базы).

Формы контактов и отзывов сохраняют новый черновик, изменённый во время PHP-запроса. Длина русского текста проверяется по символам: сообщение 5–1000, отзыв 20–1000. Локальный отзыв доступен по ссылке после сохранения; пустая тема показывает объяснение. Проверка: `npm run test:review-contact-forms` с `TOKYO_BASE_URL` / `TOKYO_STATIC_BASE_URL`.

В PHP-админке отмена брони отменяет её неотправленное подтверждение в очереди писем. Уже начатую SMTP-отправку отозвать нельзя. Проверки: `npm run test:booking-mail-cancellation` (PHP с PDO SQLite) и `npm run test:admin-booking-browser` (изолированная база и временные тестовые аккаунты, SMTP отключён).

У локальных уведомлений постоянные идентификаторы: новое бронирование не сбрасывает прочитанность старого. Старые записи обновляются при открытии кабинета. Проверка: `npm run test:notification-identity` с адресом статической версии в `TOKYO_STATIC_BASE_URL`.

«Идеальный вечер» позволяет изменить ответы, сохранив предыдущие значения. Число гостей обязательно. Растительный вариант исключает явно указанные мясные/рыбные ингредиенты по описаниям и показывает пустое состояние при отсутствии подходящего основного блюда; это не подтверждение диетического состава. Проверка: `npm run test:ideal-evening-focused`.

Конструктор: сводка показывает стоимость, число блюд и порций; рядом доступны добавление в корзину и очистка черновика. На телефоне нижняя панель возвращает к составу и скрывается при открытом меню. Проверка: `npm run test:set-draft` с `TOKYO_BASE_URL` / `TOKYO_STATIC_BASE_URL`.

Промокод можно перенести из раздела привилегий в корзину или удалить кнопкой рядом с расчётом. Изменение состава и условий скрывает устаревший расчёт; PHP повторно проверяет стоимость при оформлении. Проверка этих состояний: `npm run test:offer-quote-state` с `TOKYO_BASE_URL` / `TOKYO_STATIC_BASE_URL`.

Повтор заказа или бронирования с тем же ключом воспроизводит исходный ответ только при совпадении данных формы. Изменённые данные с прежним ключом возвращают HTTP 409; проверьте историю заявки и создайте новую отправку. Ключи старых версий без контрольного хеша также требуют проверки истории. Повторное списание или отправка новой заявки не маскируются под успех.

Omakase: пять подач доступны через карточки, кнопки «Назад/Далее» и клавиши стрелок/Home/End. На телефоне выбранная карточка остаётся видимой в горизонтальной ленте. Выбор одного из трёх форматов передаётся в бронирование через URL и сохраняется при обновлении. Проверка: `npm run test:omakase-focused` с адресами PHP/Pages в `TOKYO_BASE_URL` / `TOKYO_STATIC_BASE_URL`.

Требуется PHP 8.1+ с PDO SQLite. Для локального PHP в Windows:

```powershell
$php = (Get-Command php).Source
$ext = Join-Path (Split-Path $php) "ext"
php -d "extension_dir=$ext" -d extension=php_sqlite3.dll -d extension=php_pdo_sqlite.dll -S 127.0.0.1:8080 -t .
```

Откройте http://127.0.0.1:8080. При первом запросе создаются таблицы и загружается учебное меню. Для постоянной базы задайте переменную окружения `RESTAURANT_DB` абсолютным путём к SQLite-файлу в каталоге с правом записи. Схема и данные находятся в `schema.sql` и `seed.sql`; изменения существующей базы добавляются безопасными проверками структуры.

Создайте первого администратора из PowerShell:

```powershell
php -d "extension_dir=$ext" -d extension=php_sqlite3.dll -d extension=php_pdo_sqlite.dll .\setup_admin.php
```

Скрипт запросит email и пароль не короче 12 символов и сохранит пароль в виде хеша. Панель доступна по `/admin.php`.

## Домашний сервер и доступ из университета

Запустите `.\Start-Tokyo.ps1 -CheckOnly`, создайте администратора через `.\Start-Tokyo.ps1 -SetupAdmin`, затем запустите `.\Start-Tokyo.ps1`. Скрипт подключает PDO SQLite и закрывает доступ к служебным файлам. Настройка доступа с ноутбука, расположение базы и HTTPS описаны в [инструкции домашнего сервера](project-docs/home-hosting.md).

## Страницы и сценарии

- Главная — бренд, рекомендации, философия и форма визита.
- Главная — три вручную переключаемые hero-сцены: меню, Omakase и мастерство кухни. Автопрокрутки нет; стрелки, точки, клавиатура и режим reduced motion поддержаны.
- Меню — категории, поиск, фильтр избранного, сортировка по цене/названию, карточки с переходом к блюду.
- Страница блюда — описание, порция, учебная цена, добавление в корзину и рекомендации.
- Omakase — описание ритуала, курсы и демонстрационные варианты сетов.
- Философия — история и принципы концепции.
- Пространство — зоны, категории фотогалереи и доступный просмотр снимков.
- Бронирование — валидируемая заявка и выбор предпочтительной зоны/стола. Доступность стола не проверяется автоматически.
- Отзывы — демонстрационные записи с пометкой об их вымышленном характере и форма отправки.
- Контакты — контактная форма и условная схема вымышленной локации.
- Корзина — количество, удаление позиций, итоги, доставка/самовывоз и серверное оформление заказа. Онлайн-оплата через FreedomPay доступна только на PHP-хосте после настройки мерчанта; без неё деньги не списываются.
- Профиль — тестовый вход в локальной PHP-версии; на Pages — локальные избранные блюда, заказы, бронирования, контактные данные, адреса и очистка демо-хранилища. История поддерживает атомарный повтор заказа по текущему меню; в Pages это остаётся локальной демонстрацией.

PHP-версия сохраняет меню, пользователей, заказы, позиции заказа, заявки на бронирование, отзывы, сообщения формы и настройки в SQLite. Админка защищает вход, поддерживает CRUD меню и статусы заказов/броней/отзывов/сообщений, модерирует отзывы, управляет SEO-полями и контентом главного экрана. В панели есть поиск по меню и всем разделам с заявками, счётчики новых записей, статусы email и безопасный повтор отправки; подтверждённая бронь отображается в личном кабинете. PHP-версия отправляет письма только при корректно настроенном SMTP. Без него заявка сохраняется, а письмо остаётся в очереди; SMS не подключены. Подключение FreedomPay описано в [`project-docs/freedompay-payments.md`](project-docs/freedompay-payments.md), но мерчант ещё не настроен. GitHub Pages писем и оплату не поддерживает.

## Публичная демоверсия и ограничения

[Открыть сайт](https://altento.github.io/tokyo-premium/) · [Демо профиля и истории заказов](https://altento.github.io/tokyo-premium/account.html) · [Репозиторий](https://github.com/altento/tokyo-premium)

Чтобы просмотреть повтор заказа: откройте демо профиля, нажмите «Заполнить учебный пример» при чистом браузерном хранилище, перейдите к истории и выберите «Собрать заказ снова». Состав добавится в локальную демо-корзину без отправки заказа ресторану.

После push в `main` GitHub Actions проверяет PHP/SQLite, админку и формы, тестирует корзину, отзывы, checkout, адаптивность и визуальные состояния браузером, затем экспортирует каталог `docs` и публикует его через GitHub Pages. Исторические исправления и нынешняя модернизация описаны в `project-docs/final-acceptance-report.md` и `project-docs/final-modernization-report.md`; фактические локальные проверки перечислены в `project-docs/testing-report.md`. Pages — статический хостинг: на публичной версии нет PHP, SQLite, серверной авторизации, административной панели, отправки email и реальной оплаты. В этой версии заявки, корзина, профиль, отзывы и контакты хранятся только в `localStorage` текущего браузера; заказ или бронь не отправляются и не считаются подтверждёнными. Публичная сборка не публикует базу данных.

## Качество, изображения и редактирование

Правила визуальной системы и контента находятся в `project-docs/`. В проекте — локальные WebP-фотографии блюд и интерьера, созданные специально для концепции, а также декоративная SVG-графика. Одиннадцать пользовательских референсов сохранены в `design-references/` и не включаются в публичную Pages-сборку. Перед коммерческим запуском замените вымышленные сведения проверенными, подтвердите права на каждый публикуемый материал, добавьте серверную обработку заказов/броней и платежей и подготовьте политику обработки данных. Это учебная демоверсия, а не действующее предложение ресторана.

```sh
npm ci

TOKYO_BASE_URL=http://127.0.0.1:8090 npm run test:browser
TOKYO_BASE_URL=http://127.0.0.1:8090 TOKYO_STATIC_BASE_URL=http://127.0.0.1:8090/docs npm run test:tokyo20
TOKYO_BASE_URL=http://127.0.0.1:8090 npm run test:reviews

TOKYO_BASE_URL=http://127.0.0.1:8090 npm run test:responsive
TOKYO_BASE_URL=http://127.0.0.1:8090 npm run test:visual-states
TOKYO_BASE_URL=http://127.0.0.1:8090 TOKYO_STATIC_BASE_URL=http://127.0.0.1:8090/docs npm run test:visual-fidelity
TOKYO_BASE_URL=http://127.0.0.1:8090 TOKYO_STATIC_BASE_URL=http://127.0.0.1:8090/docs npm run test:motion
```

`npm run test:checkout` — короткая проверка повторного оформления в Pages-демоверсии: самовывоз, сброс формы, обязательность адреса доставки, повторный заказ, переход по страницам и перезагрузка. Для проверки PHP/API используйте браузерный интеграционный прогон.

Браузерный smoke-набор проверяет 11 типов страниц и базовые 21 seeded-позиции; актуальное SQLite-меню после миграций 19–20 содержит 50 публичных блюд. Отдельный набор корзины фиксирует desktop при ширине 1440 CSS px и mobile при 390 px, проверяет уникальность блюд, загруженные фото, фактическую сумму и выбранный способ получения перед созданием полноразмерных скриншотов. При съёмке фиксируется шапка в обычном потоке документа, чтобы full-page кадры не получали повторную липкую шапку. Скриншоты и состояния хранятся в `project-docs/visual-qa/`; CI сохраняет их как Actions artifact `tokyo-premium-visual-qa`.
