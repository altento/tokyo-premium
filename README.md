# Tokyo Premium — ресторан японской кухни

Существующий PHP-проект продолжен из резервной копии. Проект включает PHP 8.1+ приложение с SQLite и публичную статическую демоверсию на GitHub Pages. Все ресторанные сведения, меню, адрес, телефон, расписание, отзывы и цены придуманы для лабораторной работы.

## Запуск PHP-версии

Требуется PHP 8.1+ с PDO SQLite. Для локального PHP в Windows:

```powershell
$php = (Get-Command php).Source
$ext = Join-Path (Split-Path $php) "ext"
php -d "extension_dir=$ext" -d extension=php_sqlite3.dll -d extension=php_pdo_sqlite.dll -S 127.0.0.1:8080 -t .
```

Откройте http://127.0.0.1:8080. При первом запросе создаются таблицы и загружается учебное меню. Для постоянной базы задайте переменную окружения `RESTAURANT_DB` абсолютным путём к SQLite-файлу в каталоге с правом записи. Схема и данные находятся в `schema.sql` и `seed.sql`; изменения существующей базы добавляются безопасными проверками структуры.

Создайте первого администратора из PowerShell:

```powershell
php -d "extension_dir=$ext" -d extension=php_sqlite3.dll -d extension=php_pdo_sqlite.dll .\setup_admin.php
```

Скрипт запросит email и пароль не короче 12 символов и сохранит пароль в виде хеша. Панель доступна по `/admin.php`.

## Страницы и сценарии

- Главная — бренд, рекомендации, философия и форма визита.
- Меню — категории, поиск, фильтр избранного, сортировка по цене/названию, карточки с переходом к блюду.
- Страница блюда — описание, порция, учебная цена, добавление в корзину и рекомендации.
- Omakase — описание ритуала, курсы и демонстрационные варианты сетов.
- Философия — история и принципы концепции.
- Пространство — зоны, категории фотогалереи и доступный просмотр снимков.
- Бронирование — валидируемая заявка и выбор предпочтительной зоны/стола. Доступность стола не проверяется автоматически.
- Отзывы — демонстрационные записи с пометкой об их вымышленном характере и форма отправки.
- Контакты — контактная форма и условная схема вымышленной локации.
- Корзина — количество, удаление позиций, итоги, доставка/самовывоз и безопасное оформление без оплаты.
- Профиль — тестовый вход в локальной PHP-версии; на Pages — локальные избранные блюда, заказы, бронирования, контактные данные, адреса и очистка демо-хранилища.

PHP-версия сохраняет меню, пользователей, заказы, позиции заказа, заявки на бронирование, отзывы, сообщения формы и настройки в SQLite. Админка защищает вход, поддерживает CRUD меню и статусы заказов/броней/отзывов/сообщений, модерирует отзывы, управляет SEO-полями и контентом главного экрана.

## Публичная демоверсия и ограничения

[Открыть сайт](https://altento.github.io/tokyo-premium/) · [Репозиторий](https://github.com/altento/tokyo-premium)

После push в `main` GitHub Actions проверяет PHP/SQLite, админку и формы, тестирует корзину, отзывы, checkout, адаптивность и визуальные состояния браузером, затем экспортирует каталог `docs` и публикует его через GitHub Pages. Полный список проверок, скриншоты и ограничения описаны в `project-docs/final-acceptance-report.md`. Pages — статический хостинг: на публичной версии нет PHP, SQLite, серверной авторизации, административной панели, отправки email и реальной оплаты. В этой версии заявки, корзина, профиль, отзывы и контакты хранятся только в `localStorage` текущего браузера; заказ или бронь не отправляются и не считаются подтверждёнными. Публичная сборка не публикует базу данных.

## Качество, изображения и редактирование

Правила визуальной системы и контента находятся в `project-docs/`. В проекте — локальные WebP-фотографии блюд и интерьера, созданные специально для концепции, а также декоративная SVG-графика. Одиннадцать пользовательских референсов сохранены в `design-references/` и не включаются в публичную Pages-сборку. Перед коммерческим запуском замените вымышленные сведения проверенными, подтвердите права на каждый публикуемый материал, добавьте серверную обработку заказов/броней и платежей и подготовьте политику обработки данных. Это учебная демоверсия, а не действующее предложение ресторана.

```sh
npm ci
npm run test:cart
npx playwright install chromium
php tests/php_integrity_integration.php
RESTAURANT_DB=/tmp/tokyo-browser.sqlite php -S 127.0.0.1:8090 -t .
TOKYO_BASE_URL=http://127.0.0.1:8090 npm run test:browser
TOKYO_BASE_URL=http://127.0.0.1:8090 npm run test:reviews
TOKYO_BASE_URL=http://127.0.0.1:8090 npm run test:cart-visual
TOKYO_BASE_URL=http://127.0.0.1:8090 npm run test:responsive
TOKYO_BASE_URL=http://127.0.0.1:8090 npm run test:visual-states
```

Браузерный прогон проверяет 11 типов страниц, все 20 карточек блюд, пользовательские сценарии и целевые ширины от 320 до 1920 px. Скриншоты desktop/mobile и состояния корзины хранятся в `project-docs/visual-qa/`; CI сохраняет их как Actions artifact `tokyo-premium-visual-qa`.
